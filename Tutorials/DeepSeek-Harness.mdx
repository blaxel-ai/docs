Move your current DeepSeek Harness (DSH) Web session into a private Blaxel sandbox so the agent can keep working while your computer is offline. In this walkthrough, you add invoice status filters, bring the tested changes back to your local repository, and move the same session again.

## Prerequisites

- A [Blaxel account](https://blaxel.ai) and workspace
- Node.js 22.19.0 or newer in Node.js 22, or Node.js 24 or newer
- Git, npm, and pnpm on your computer
- A portable API key for the native DeepSeek or pi-ai model you select in DSH
- A local Git worktree; the steps below create one from the Invoice Desk example

The commands select the current plugin release. The launcher selects its compatible DSH runtime. DSH is in developer preview.

Tested with plugin 0.1.3 candidate and DSH 0.1.2-rc.1. Before publication, verify that `@latest` includes cloud handoff and recapture the public installation.

## 1. Install the plugin and open DSH

Install the plugin in the Web profile:

```bash
npx --yes --package @blaxel/dsh-sandbox@latest \
  dsh-blaxel plugin --profile web add \
  --allow-build=@deepseek-ai/dsh-subprocess-local \
  --allow-build=koffi --allow-build=node-pty \
  --allow-build=@google/genai --allow-build=protobufjs \
  @blaxel/dsh-sandbox@latest
```

Wait for installation to finish, then open the Web interface:

```bash
npx --yes --package @blaxel/dsh-sandbox@latest dsh-blaxel web
```

The launcher prepares the compatible runtime, including native conversation import support. Its first run downloads dependencies. Later runs reuse the cache. Use this launcher for subsequent visits, and keep the same `DSH_HOME` if you configure a custom profile.

## 2. Prepare and open Invoice Desk

The [Invoice Desk starter](https://github.com/blaxel-ai/deepseek-harness-blaxel-sandbox/tree/main/examples/invoice-desk) already has CSV export and ten tests. Copy it into a small repository of its own so the handoff contains the application you are changing:

```bash
git clone https://github.com/blaxel-ai/deepseek-harness-blaxel-sandbox.git deepseek-blaxel-source
cp -R deepseek-blaxel-source/examples/invoice-desk invoice-desk
cd invoice-desk
git init
npm test
```

The starter tests should pass. In DSH, select Add workspace, choose the `invoice-desk` directory, and open it. Start a conversation in that workspace.

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/open-repository-2x.webp" alt="Select the Invoice Desk directory in the workspace browser" width="680" style={{ height: "auto", maxWidth: "100%" }} />

The directory-selection image uses DSH's browser-based folder picker. A desktop installation can show the native operating-system picker instead; choose the same project directory.

Open Settings > Blaxel. Select Sign in to Blaxel and complete browser authorization, then choose your workspace and Verify connection. An existing `bl login` profile also appears here. Use an API key instead exposes the workspace and API-key form when you need that sign-in method.

Under Sandbox defaults, choose 4 GB memory. Expand Advanced settings, select Typescript App, leave Region on Automatic, and choose a maximum lifetime suitable for the task. This run uses 1 hour. Select Save defaults when you change a value.

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/defaults-2x.webp" alt="Sandbox defaults with 4 GB memory, Typescript App, automatic region, and a one-hour lifetime" width="556" style={{ height: "auto", maxWidth: "100%" }} />

These defaults affect new sandboxes. Cloud sessions otherwise use a 24-hour maximum lifetime. Choose enough time to return the work before the sandbox expires.

<Note>
  The selected model's portable API key enters the private cloud host so the agent can run independently. Blaxel credentials stay on your computer. Local OAuth grants, laptop-only model endpoints, external skills, and host MCP configuration do not migrate.
</Note>

<Warning>
  The cloud agent has full access inside its dedicated VM without per-tool approval. Use a model and project tools you trust with the model API key. Keep credentials out of the project files.
</Warning>

## 4. Start the task locally

Send this prompt in the local conversation:

```text wrap
Read README.md, server.mjs and invoices.mjs. I want an invoice status filter with All, Paid and Pending options, keeping Export CSV. Give me a short implementation plan. Do not edit files yet. Do not read credentials or environment variables. Do not delegate.
```

After the plan, paste the implementation prompt below into the composer. Leave it unsent so you can see the draft travel with the conversation:

```text wrap
Implement that invoice status filter now. Add All, Paid and Pending links to the billing page using a status query parameter, and have the CSV export respect the selected status. Keep the existing layout and amount formatting. Add focused node:test checks for filtering without mutating the input and for unknown status values. Run npm test and verify the HTTP page and CSV routes using Node fetch against a temporary server. Stop that server afterward. Give a concise summary of the changed files and actual checks. Do not read credentials or environment variables. Do not delegate or ask follow-up questions.
```

## 5. Move the session to Blaxel

Select Move to Blaxel. The launch panel reports workspace preparation, sandbox startup, and conversation restoration. Wait for the private cloud page to open and show Your session is on Blaxel.

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/launch-2x.webp" alt="Handoff progress from the Git worktree to the cloud agent" width="370" style={{ height: "auto", maxWidth: "100%" }} />
<img className="hidden dark:block" src="/img/deepseek-harness/walkthrough/launch-2x.webp" alt="Handoff progress from the Git worktree to the cloud agent" width="370" style={{ height: "auto", maxWidth: "100%" }} />

The plugin copies tracked files and unignored untracked files, including current edits. It restores the native conversation, referenced images, and pending draft. A running root task can move at a safe tool boundary; wait for local child agents to finish before moving.

<Warning>
  Git-ignored files, `.git`, `.dsh-blaxel`, common credential files, and private keys are excluded from the snapshot. Install any project dependencies required inside the sandbox. Invoice Desk needs no extra packages.
</Warning>

Confirm the implementation prompt is still in the cloud composer, then send it. Model requests, tools, and new conversation history now run in the sandbox. Once the cloud page is ready, closing the original DSH process does not stop that cloud agent.

The local conversation is read-only while Blaxel owns execution:

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/local-read-only-2x.webp" alt="Original local conversation is read-only while the cloud owns execution" width="720" style={{ height: "auto", maxWidth: "100%" }} />

Copy private link provides access to the cloud session from another browser. Treat the link as a credential. Links expire after 24 hours; reopening through Open cloud session on the original computer renews access. Link renewal does not extend the sandbox's lifetime.

<Tip>
  If access fails, reopen the session through the original DSH launcher and use its fresh private link. If Chrome still blocks it, investigate the browser restriction; do not make the sandbox public to bypass the error.
</Tip>

## 6. Verify the cloud work

Read the agent's actual test output before returning. The example started with ten tests; the captured run finishes with thirteen passing tests, including the new filter and HTTP checks. An agent can stop with an incomplete result, so verify its output rather than assuming the first response means success.

In this run, the first response imported an unavailable fetch library. Start by asking the agent to use Node's built-in fetch:

```text wrap
Finish the requested verification now. Use Node's built-in global fetch, with no fetch-library imports and no new dependencies. Read the test files first, fix any failed test or route, run npm test until it passes, and stop any temporary server. Do not inspect credentials or environment variables. Do not delegate or ask follow-up questions. Report only the actual passing test count and changed files.
```

The HTTP tests also needed an explicit loopback host and port for their temporary server, instead of inheriting the cloud host's port. Status assertions needed to check table rows because the navigation contains every status label. We corrected those issues and verified all thirteen tests independently.

Review the changed source as well. If a text file unexpectedly appears as a binary patch, cancel the return and have the agent inspect and correct it before proceeding.

## 7. Review and bring the session back

On your original computer, start DSH with the same profile and launcher. Select Move back to local in the cloud page or the local Blaxel settings. Review the changed paths and actual patch, then select Apply changes and move back.

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/return-light-2x.webp" alt="Review the README patch before applying changes and returning locally" width="720" style={{ height: "auto", maxWidth: "100%" }} />
<img className="hidden dark:block" src="/img/deepseek-harness/walkthrough/return-dark-2x.webp" alt="Review the README patch before applying changes and returning locally" width="720" style={{ height: "auto", maxWidth: "100%" }} />

The example review above comes from the second handoff's README update. Your first return lists the application and test changes. The review always reflects the current sandbox's changes.

The return checks the patch against the current local worktree before writing. It checkpoints the cloud root, waits for active child agents, imports the conversation and supported child histories, restores the pending draft and original local permissions, then stops the sandbox after the files and history are durable locally.

In a terminal inside `invoice-desk`, run:

```bash
npm test
npm start
```

Open `http://localhost:3000`. Select Pending and confirm only the pending invoice appears. Select Paid and All to check the other views. Export CSV follows the chosen filter.

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/pending-result-2x.webp" alt="Invoice Desk Pending filter shows one invoice and Export CSV" width="720" style={{ height: "auto", maxWidth: "100%" }} />

You can inspect the filtered CSV response independently in another terminal:

```bash
curl --fail 'http://localhost:3000/export.csv?status=Pending'
```

Expect a header and one pending invoice. The captured checks also verified three rows for All and two for Paid. If Chrome blocks an attachment download, keep browser download verification separate from a passing HTTP check. Stop the example server with Ctrl+C when finished.

## 8. Move the updated session again

Add a short local checkpoint to `README.md` and save it. For example:

```markdown
## Local checkpoint

The status filter and filtered CSV export are working locally.
```

In the same returned conversation, paste this prompt and leave it unsent:

```text wrap
Read README.md and add a short Status filters section explaining All, Paid and Pending and that Export CSV follows the selection. Preserve the existing Local checkpoint section. Run npm test. Do not change application code, inspect credentials or environment variables, or delegate. Summarize in one sentence.
```

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/second-handoff-clean-2x.webp" alt="New README task ready to move with the returned local session" width="712" style={{ height: "auto", maxWidth: "100%" }} />
<img className="hidden dark:block" src="/img/deepseek-harness/walkthrough/second-handoff-clean-2x.webp" alt="New README task ready to move with the returned local session" width="712" style={{ height: "auto", maxWidth: "100%" }} />

Select Move to Blaxel again. The new sandbox starts with the earlier cloud changes, your new local checkpoint, and the same conversation. Send the prompt from the cloud page. After the tests pass, review and return the README change. Check that both the Status filters section and Local checkpoint remain locally.

Reopening an existing sandbox reconnects to its current files. It does not upload newer local edits. Files transfer when you move and return the session; this is not continuous synchronization.

## 9. Recover safely and finish

If local edits conflict with the return patch, the plugin keeps both copies, leaves the sandbox available, and identifies a recovery patch under the repository's private Git directory. Preserve your local edits, resolve the conflicting file changes, and retry Move back to local.

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/conflict-2x.webp" alt="Return conflict message preserves local files and identifies the recovery patch" width="720" style={{ height: "auto", maxWidth: "100%" }} />
<img className="hidden dark:block" src="/img/deepseek-harness/walkthrough/conflict-2x.webp" alt="Return conflict message preserves local files and identifies the recovery patch" width="720" style={{ height: "auto", maxWidth: "100%" }} />

Restarting the original DSH host does not require a new sandbox. Reopen the same profile and session, then use Open cloud session or retry the return. If an import was interrupted, retry from that original profile so the durable transfer receipts can resume completed work.

After a successful return, Settings > Blaxel no longer lists an active sandbox for that session:

<img className="block dark:hidden" src="/img/deepseek-harness/walkthrough/cleanup-2x.webp" alt="Blaxel settings show no sessions running after return" width="556" style={{ height: "auto", maxWidth: "100%" }} />
<img className="hidden dark:block" src="/img/deepseek-harness/walkthrough/cleanup-2x.webp" alt="Blaxel settings show no sessions running after return" width="556" style={{ height: "auto", maxWidth: "100%" }} />

<Warning>
  Discard permanently removes unreturned cloud work. Sandbox expiry also makes remote-only work unavailable. Return the changes you need before discarding the sandbox or reaching its maximum lifetime.
</Warning>

For transfer limits, supported session data, and additional recovery cases, read the [cloud handoff contract](https://github.com/blaxel-ai/deepseek-harness-blaxel-sandbox/blob/main/docs/cloud-session-handoff.md).
