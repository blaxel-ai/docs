This page lists Blaxel prices, the quotas of each tier, request size and rate limits, and regions in one place. Values were last reviewed on 2026-10-21. Your account can have higher limits than its tier: the [Quotas page of the Blaxel Console](https://app.blaxel.ai/account/quotas) shows the values that apply to you.

## Pricing

Compute is billed by the second for the memory you allocate, and CPU scales with memory. The rates below are the pay-as-you-go rates published on [blaxel.ai/pricing](https://blaxel.ai/pricing).

| --- | --- | --- |
| Sandboxes | Active compute, by allocated memory | $0.0000115 per GB-second |
| Sandboxes | Snapshot storage | $0.20 per GB-month |
| Sandboxes, jobs and MCP servers | Image storage | $0.045 per GB-month |
| Batch jobs | Compute, by memory | $0.000006 per GB-second |
| Batch jobs | Cron jobs | Included |
| MCP servers | Compute, by memory | $0.000007 per GB-second |

A sandbox in standby doesn't use compute: you pay only for its snapshot and volume storage. See [sandbox lifecycle](/Sandboxes/Overview#sandbox-lifecycle).

## Quota tiers

Your tier rises with the top-ups you made in the past 30 days, and each tier includes the quotas of the tiers below it. Promotional credits don't count toward a tier. Quotas apply to your whole account, across all its workspaces. See [usage and quotas](/Security/Quotas) for how tiers are calculated and how to request an increase.

## Sandbox resources

By default, Blaxel allocates vCPUs from the memory you set.

| Memory | vCPUs |
| --- | --- |
| Up to 2 GB | 1 |
| Up to 4 GB | 2 |
| Up to 8 GB | 4 |
| Up to 16 GB | 6 |
| Up to 32 GB | 8 |
| Up to 64 GB | 16 |
| More than 64 GB | 32 |

| Limit | Value | When exceeded |
| --- | --- | --- |
| Minimum sandbox memory | 1 GB | Smaller values are raised to the minimum |
| Maximum sandbox memory | 256 GB | Your tier's memory quota applies first: `QUOTA_EXCEEDED` (429) |
| Minimum `ttl` and `ttl-max-age` | 5 minutes | Rejected with a 400 error |
| Minimum `ttl-idle` | 1 minute | Rejected with a 400 error |
| Maximum `terminationGracePeriodSeconds` and `standbyGracePeriodSeconds` | 5 minutes | Rejected with a 400 error |
| Default timeout of a `keepAlive` process | 10 minutes | The process is stopped; set `timeout` to `0` to run until it exits |
| Maximum `waitForCompletion` wait | 1 minute | The call returns an error while the process keeps running; watch the process instead |
| Idle WebSocket or TCP connection | 15 minutes | The connection closes and the sandbox can go on standby |

## Request and payload sizes

| Limit | Value | When exceeded |
| --- | --- | --- |
| Single HTTP request body to a sandbox (`mk3.0`) | 8 MiB (8,388,608 bytes) | 413 with a plain HTML body; upload in parts with the multipart endpoints. Sandboxes on `mk3.1` don't apply this limit |
| SDK multipart upload threshold and part size | 5 MiB (5,242,880 bytes) | SDK `write()`, `writeBinary()` and `write_binary()` split larger files into parts of this size |
| Parts per multipart upload | 10,000 | The part is rejected |
| Single process stdin write | 8 MiB (8,388,608 bytes) | 413; send larger input in several writes |
| JSON body merged by proxy secrets injection | 1 MB | The request is forwarded without injected body fields |

See [write binary file](/Sandboxes/Filesystem#write-binary-file) for multipart uploads, and [error codes](/troubleshooting/error-codes) for the structured errors.

## Regions

| Region code | Location | Country |
| --- | --- | --- |
| `us-pdx-1` | Oregon | United States |
| `us-was-1` | North Virginia | United States |
| `eu-lon-1` | London | United Kingdom |
| `eu-fra-1` | Frankfurt | Germany |
| `auto` | Automatic (your closest region) | - |

Set `region` to `auto` to let Blaxel pick the closest region. To allowlist Blaxel traffic, retrieve the [public IP addresses](/Infrastructure/Regions#public-ip-addresses) of each region from the API: they are not listed here because they change as the platform scales.
