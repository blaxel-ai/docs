</Note>

[Proxy routing rules](/Sandboxes/Proxy-secrets-injection) can carry their own `secrets`, but those live inside one sandbox's configuration and have to be repeated in every sandbox that needs them. A **workspace secret** is stored once, server-side, and any routing rule in the workspace can reference it as `{{SECRET:name}}`.

Each workspace secret is **scoped to destinations**: the hosts (optionally with a path glob) it may be sent to. The proxy only substitutes the placeholder when the outbound request matches one of them; toward any other destination the placeholder is left unresolved. Values are **write-only**: they can be set or rotated, never read back.

## How it works

1. You create a secret with a name, a value and its destinations (console, API, CLI or SDK).
2. Blaxel stores a new immutable version and replicates it to the proxy in every region. Replication is asynchronous and retried for up to two hours if a region is unreachable, so the request succeeds even while a region is down.
3. A sandbox routing rule references `{{SECRET:name}}` in a header or body field.
4. When the sandbox sends a request, the proxy resolves the placeholder only if the request's host and path match one of the secret's destinations.

Resolution order inside the proxy is: the matched routing rule's own `secrets`, then workspace secrets whose destinations match the request. A name declared nowhere stays unresolved.

## Destinations

Destinations use the same syntax as `routing[].destinations`:

| Destination | Matches |
|---|---|
| `api.stripe.com` | any path on that host |
| `*.example.com` | any subdomain of example.com |
| `api.example.com/v1/*` | paths under `/v1/` on that host |
| `api.example.com/v1/charges` | that exact path |

A secret needs at least one destination and at most 50, each at most 512 characters. `*` alone is rejected: a workspace secret must name the hosts it may reach.

## Create a secret

  <Tab title="Console">
    Open your workspace, go to **Secrets** (in the proxy section), click **Add secret**, enter the name, the value and one destination per line (or comma-separated), and save. The table shows each secret's destinations and dates; use **Rotate** to change the value or destinations (the current destinations are pre-filled).

    ```bash
    # value from a flag
    bl secret set stripe-key --value sk_live_... --destination api.stripe.com

    # value from stdin, several destinations
    echo -n "$GITHUB_TOKEN" | bl secret set github-token \
      -d api.github.com -d "uploads.github.com/repos/*"

    bl secret list
    bl secret delete stripe-key
    ```
  </Tab>

## Use it from a sandbox

Reference the secret from a routing rule like any other placeholder. The rule's `destinations` decide which requests go through it; the secret's destinations decide where the value may be injected.

<CodeGroup>

```typescript TypeScript
import { SandboxInstance } from "@blaxel/core";

const sandbox = await SandboxInstance.create({
  name: "my-sandbox",
  image: "blaxel/base-image:latest",
  region: "us-was-1",
  network: {
    proxy: {
      routing: [
        {
          destinations: ["api.stripe.com"],
          headers: { Authorization: "Bearer {{SECRET:stripe-key}}" },
        },
      ],
    },
  },
});
```

```python Python
from blaxel.core import SandboxInstance

sandbox = await SandboxInstance.create({
    "name": "my-sandbox",
    "image": "blaxel/base-image:latest",
    "region": "us-was-1",
    "network": {
        "proxy": {
            "routing": [
                {
                    "destinations": ["api.stripe.com"],
                    "headers": {"Authorization": "Bearer {{SECRET:stripe-key}}"},
                }
            ]
        }
    },
})
```

</CodeGroup>

Code inside the sandbox can also send `{{SECRET:stripe-key}}` in its own request headers or body; the proxy resolves it under the same destination check.

<Warning>
  If a rule sends `{{SECRET:stripe-key}}` toward a host that is not among the secret's destinations, the placeholder is **not** resolved and the request goes out with the literal text. Scope the secret to every host that legitimately needs it.
</Warning>

## Rotation and deletion

- **Rotate** by setting the same name again (console **Rotate**, `bl secret set`, `POST /secrets`). The new value and destinations replace the old ones in every region within seconds; sandboxes pick it up on their next request.
- **Delete** removes every version and stops injection everywhere. Deleting a name that no longer exists is a no-op.
- A region that is unreachable when you write converges on its own once it is back; no need to retry the write.
