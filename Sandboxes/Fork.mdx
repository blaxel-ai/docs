</Note>

A snapshot captures the state of a sandbox at a point in time: its filesystem, its running processes, and its memory. Use snapshots to checkpoint a sandbox before a risky change, to roll it back later, or as the basis for forking a new sandbox.

A snapshot outlives the sandbox it was captured from: it stays usable, and forkable, after that sandbox is deleted.

## Create a snapshot

Capture a snapshot from the sandbox you want to checkpoint. Snapshot names are unique across your workspace, and creating a snapshot with a name that is already taken fails with a `409` error.

<CodeGroup>

```typescript TypeScript
import { SandboxInstance } from "@blaxel/core";

const sandbox = await SandboxInstance.get("my-sandbox");
const snapshot = await sandbox.snapshots.create("my-snapshot");
```

```python Python
from blaxel.core import SandboxInstance

sandbox = await SandboxInstance.get("my-sandbox")
snapshot = await sandbox.snapshots.create("my-snapshot")
```

```bash HTTP API
curl -X POST https://api.blaxel.ai/v0/sandboxes/my-sandbox/snapshots \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace"
```

</CodeGroup>

You can also create a snapshot without retrieving the sandbox first, by passing it as `source`:

<CodeGroup>

```typescript TypeScript
import { Snapshot } from "@blaxel/core";

const snapshot = await Snapshot.create({
  name: "my-snapshot",
  source: { name: "my-sandbox" },
});
```

```python Python
from blaxel.core import Snapshot

snapshot = await Snapshot.create({
    "name": "my-snapshot",
    "source": {"name": "my-sandbox"},
})
```

```bash HTTP API
curl -X POST https://api.blaxel.ai/v0/snapshots \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "my-snapshot",
    "source": { "name": "my-sandbox" }
  }'
```

</CodeGroup>

<Note>
  `POST /sandboxes/{name}/snapshots` generates the snapshot name for you, so it cannot collide with an existing one. Use `POST /snapshots` with a `source` to choose the name.
</Note>

## List snapshots

List from a sandbox to get only the snapshots captured from it:

<CodeGroup>

```typescript TypeScript
import { SandboxInstance } from "@blaxel/core";

const sandbox = await SandboxInstance.get("my-sandbox");
const snapshots = await sandbox.snapshots.list();
```

```python Python
from blaxel.core import SandboxInstance

sandbox = await SandboxInstance.get("my-sandbox")
snapshots = await sandbox.snapshots.list()
```

```bash HTTP API
curl https://api.blaxel.ai/v0/sandboxes/my-sandbox/snapshots \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace"
```

</CodeGroup>

List all your snapshots to also get the ones whose source sandbox no longer exists:

<CodeGroup>

```typescript TypeScript
import { Snapshot } from "@blaxel/core";

const snapshots = await Snapshot.list({ limit: 50 });
for await (const snapshot of snapshots) {
  console.log(snapshot.name);
}
```

```python Python
import asyncio
from blaxel.core import Snapshot

async def main():
    snapshots = await Snapshot.list(limit=50)
    async for snapshot in snapshots.auto_paging_iter():
        print(snapshot.name)

asyncio.run(main())
```

```shell Blaxel CLI
bl get snapshots
```

</CodeGroup>

The list endpoint is cursor-paginated and supports full-text search on the snapshot name, source name, and status through the `q` parameter. Refer to the [API reference documentation](/api-reference/introduction#pagination) for how to page through the results.

## Restore a sandbox to a snapshot

Restoring rolls a sandbox back to one of its own snapshots, in place. The sandbox keeps its name, its URLs, its previews, and its configuration: only the instance behind it is torn down and rebuilt from the snapshot, on the same machine the snapshot was taken on.

<Warning>
  Everything the sandbox wrote after the snapshot was taken is lost: files, running processes, and memory state. Take a new snapshot first if you want to be able to come back to the current state.
</Warning>

<CodeGroup>

```typescript TypeScript
import { SandboxInstance } from "@blaxel/core";

const sandbox = await SandboxInstance.get("my-sandbox");
await sandbox.snapshots.restore("my-snapshot");
```

```python Python
from blaxel.core import SandboxInstance

sandbox = await SandboxInstance.get("my-sandbox")
await sandbox.snapshots.restore("my-snapshot")
```

```bash HTTP API
curl -X POST https://api.blaxel.ai/v0/sandboxes/my-sandbox/snapshots/my-snapshot/restore \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace"
```

</CodeGroup>

The restore returns as soon as it is accepted, without waiting for the sandbox to be back up. The sandbox answers again once its instance has been rebuilt, so retry your first calls while it resumes.

Only a snapshot of that same sandbox can be restored, and only once it is `ready`. To roll back onto a different sandbox, [fork from the snapshot](#fork-from-a-snapshot) instead.

You can also restore from the Blaxel console: open your sandbox, go to the **Snapshots** tab, and use the **Restore** action on the snapshot you want to go back to.

## Fork a sandbox

Forking creates a new sandbox from an existing one, forking its entire memory state (files + running processes). The fork inherits the source sandbox's image, memory configuration, environment variables, and port settings.

Calling `fork()` automatically snapshots the source sandbox's current state and forks from it. You don't need to create a snapshot first.

<CodeGroup>

```typescript TypeScript
import { SandboxInstance } from "@blaxel/core";

const sandbox = await SandboxInstance.get("my-sandbox");
const result = await sandbox.fork("my-sandbox-copy");
```

```python Python
from blaxel.core import SandboxInstance

sandbox = await SandboxInstance.get("my-sandbox")
result = await sandbox.fork("my-sandbox-copy")
```

```bash CLI
bl fork sbx/my-sandbox sbx/my-sandbox-copy
```

```bash HTTP API
curl -X POST https://api.blaxel.ai/v0/sandboxes/my-sandbox/fork \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace" \
  -H "Content-Type: application/json" \
  -d '{
    "targetType": "sandbox",
    "targetName": "my-sandbox-copy"
  }'
```

</CodeGroup>

### Fork from a snapshot

To create a sandbox from a snapshot you took earlier, pass its name as `snapshotId`. The fork is created from that snapshot instead of the source sandbox's current state:

<CodeGroup>

```typescript TypeScript
import { SandboxInstance } from "@blaxel/core";

const sandbox = await SandboxInstance.get("my-sandbox");
const result = await sandbox.fork("my-sandbox-copy", {
  targetType: "sandbox",
  snapshotId: "my-snapshot",
});
```

```python Python
from blaxel.core import SandboxInstance

sandbox = await SandboxInstance.get("my-sandbox")
result = await sandbox.fork(
    "my-sandbox-copy",
    target_type="sandbox",
    snapshot_id="my-snapshot",
)
```

```bash HTTP API
curl -X POST https://api.blaxel.ai/v0/sandboxes/my-sandbox/fork \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace" \
  -H "Content-Type: application/json" \
  -d '{
    "targetType": "sandbox",
    "targetName": "my-sandbox-copy",
    "snapshotId": "my-snapshot"
  }'
```

</CodeGroup>

A snapshot carries the image, the memory size, the ports, the infrastructure generation, the region, and the volumes of what it captured, so you can also fork it directly, even after its source sandbox is deleted:

<CodeGroup>

```typescript TypeScript
import { Snapshot } from "@blaxel/core";

const snapshot = await Snapshot.get("my-snapshot");
const result = await snapshot.fork("my-new-sandbox");
```

```python Python
from blaxel.core import Snapshot

snapshot = await Snapshot.get("my-snapshot")
result = await snapshot.fork("my-new-sandbox")
```

```bash HTTP API
curl -X POST https://api.blaxel.ai/v0/snapshots/my-snapshot/fork \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace" \
  -H "Content-Type: application/json" \
  -d '{
    "targetType": "sandbox",
    "targetName": "my-new-sandbox"
  }'
```

</CodeGroup>

Set `targetType` to `application` to start an [application](/Applications/Overview) from the snapshot instead of a sandbox.

When the source sandbox still exists, the fork also inherits what the snapshot does not carry, such as environment variables, lifecycle policies, and network configuration. When the source sandbox is gone, the fork runs with the configuration stored on the snapshot.

### Fork with new environment variables

Pass `envs` to give the fork a different environment from its source. Each variable the source already carries takes the value you pass, each variable it does not carry is added, and every other variable of the source is inherited. The source sandbox is left untouched.

<CodeGroup>

```typescript TypeScript
import { SandboxInstance } from "@blaxel/core";

const sandbox = await SandboxInstance.get("my-sandbox");
const result = await sandbox.fork("my-sandbox-copy", {
  envs: [
    { name: "NODE_ENV", value: "staging" },
    { name: "FEATURE_FLAG", value: "1" },
  ],
});
```

```python Python
from blaxel.core import SandboxInstance
from blaxel.core.client.models.env import Env

sandbox = await SandboxInstance.get("my-sandbox")
result = await sandbox.fork(
    "my-sandbox-copy",
    envs=[
        Env(name="NODE_ENV", value="staging"),
        Env(name="FEATURE_FLAG", value="1"),
    ],
)
```

```bash HTTP API
curl -X POST https://api.blaxel.ai/v0/sandboxes/my-sandbox/fork \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace" \
  -H "Content-Type: application/json" \
  -d '{
    "targetType": "sandbox",
    "targetName": "my-sandbox-copy",
    "envs": [
      { "name": "NODE_ENV", "value": "staging" },
      { "name": "FEATURE_FLAG", "value": "1" }
    ]
  }'
```

</CodeGroup>

The fork starts with the new environment already applied, so processes you launch in it read the new values. Processes that were already running in the source when it was snapshotted keep the environment they were started with, as an environment change cannot reach a process that is already running.

<Note>
  `envs` only sets and adds variables. A variable of the source cannot be removed through a fork.
</Note>

`envs` works the same way when forking from a snapshot.

### Fork request parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `targetType` | string | Target resource type: `sandbox` or `application` |
| `targetName` | string | Name of the resource to create |
| `port` | integer | Port to expose |
| `snapshotId` | string | Name of the snapshot to fork from, instead of the current state |
| `envs` | array | Environment variables the fork runs with, on top of the ones inherited from the source |

## Delete a snapshot

Deleting a snapshot from the sandbox it was captured from, or by its name, does the same thing: the snapshot is gone.

<CodeGroup>

```typescript TypeScript
import { SandboxInstance, Snapshot } from "@blaxel/core";

const sandbox = await SandboxInstance.get("my-sandbox");
await sandbox.snapshots.delete("my-snapshot");

await Snapshot.delete("my-snapshot");
```

```python Python
from blaxel.core import SandboxInstance, Snapshot

sandbox = await SandboxInstance.get("my-sandbox")
await sandbox.snapshots.delete("my-snapshot")

await Snapshot.delete("my-snapshot")
```

```bash HTTP API
curl -X DELETE https://api.blaxel.ai/v0/snapshots/my-snapshot \
  -H "Authorization: Bearer $BL_API_KEY" \
  -H "X-Blaxel-Workspace: my-workspace"
```

```shell Blaxel CLI
bl delete snapshot my-snapshot
```

</CodeGroup>

Deleting a snapshot is the only thing that removes it. Snapshots have no expiration, and Blaxel never prunes them for you.

## Snapshots and sandbox deletion

Deleting a sandbox does not delete its snapshots. They keep their names and stay forkable, with `source.deleted` set to `true` to tell you their sandbox is gone.

<Warning>
  Snapshots keep consuming storage after their source sandbox is deleted, and they count against your workspace snapshot quota. Delete the snapshots you no longer need. Refer to [quotas](/Security/Quotas) for the limits that apply to your workspace.
</Warning>
