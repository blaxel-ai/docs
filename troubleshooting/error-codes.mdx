Blaxel returns structured error responses in case of request failure. These error responses include additional information designed for coding agents and LLMs.

Structured platform errors have a consistent JSON body and response header, as shown below:

```json
{
  "error": {
    "action": "Stop. URL does not match a Blaxel route. Use `https://{sbx|agt|mcp|mdl|job}-{name}-{workspace}.{region}.bl.run[/{path}]` for workloads or `https://{preview_id}.preview.bl.run/{path}` for previews. Get the canonical URL from the SDK (e.g. `sandbox.metadata.url`), not by hand.",
    "code": "ROUTE_NOT_FOUND",
    "dispatch_state": "not_dispatched",
    "do_not": "Do not retry, do not guess URLs, do not use `run.blaxel.ai` (not served).",
    "docs_url": "https://docs.blaxel.ai/Sandboxes/Ports.md",
    "message": "Preview not found: xxx",
    "origin": "platform",
    "retryable": false,
    "safe_to_retry_request": false,
    "status": 404,
    "timestamp": "2026-04-23T14:49:43+00:00"
  }
}
```

| Field | Description |
|---|---|
| `error.action` | Agent-readable actions to be taken |
| `error.code` | Machine-readable error code |
| `error.dispatch_state` | `not_dispatched` when the request never reached the workload, `dispatched_unknown` when it may have |
| `error.do_not` | Agent-readable actions not to be taken |
| `error.docs_url` | Documentation related to this error |
| `error.message` | Human-readable description |
| `error.origin` | `"platform"` when emitted by Blaxel; otherwise absent |
| `error.retryable` | Whether the request can return a different response if it is retried |
| `error.safe_to_retry_request` | `true` only when the request can be replayed safely, including a write |
| `error.status` | HTTP status code (same as HTTP response header) |
| `error.timestamp` | Timestamp in ISO-8601 format |

## Error codes

Every code has its own anchor on this page, and an error's `docs_url` links to it: `FEATURE_NOT_ENABLED` sends `https://docs.blaxel.ai/troubleshooting/error-codes#feature-not-enabled`, for example. Codes are grouped by the service that answers:

- [Gateway](#gateway): requests to workload and preview URLs (`*.bl.run`).
- [Control plane](#control-plane): the Blaxel API (`api.blaxel.ai`), which the console, the CLI and the SDKs call to manage resources.
- [Sandbox API](#sandbox-api): calls a sandbox serves itself, such as processes, files and drives.

A code that more than one service returns has a row in each table. In messages, `{name}` stands for a value filled in when the error is sent.

### Control plane

The control plane sends the same fields at the top level of its `/v0` error body, next to the `error` (the message) and `code` (the HTTP status, an integer) fields it has always sent. The string code is in `error_code`, and `request_id` identifies the request for support. Codes that name a resource, a state or a field add it to the body, as their rows say.

```json
{
  "error": "user \"<subject>\" has no role in workspace \"<workspace>\" (required: \"viewer\")",
  "code": 403,
  "error_code": "WORKSPACE_ACCESS_DENIED",
  "message": "user \"<subject>\" has no role in workspace \"<workspace>\" (required: \"viewer\")",
  "action": "Check that the X-Blaxel-Workspace header (or the workspace query parameter) names a workspace this credential belongs to; the workspace may also not exist. If it is the right workspace, ask one of its admins for the role named in the message.",
  "do_not": "Do not cycle through other workspace names, and do not retry: the answer stays the same until the credential gets a role there.",
  "docs_url": "https://docs.blaxel.ai/troubleshooting/error-codes#workspace-access-denied",
  "retryable": false,
  "safe_to_retry_request": false,
  "dispatch_state": "not_dispatched",
  "status": 403,
  "origin": "platform",
  "timestamp": "2026-11-18T21:03:58.123Z",
  "request_id": "4bf92f3577b34da6a3ce929d0e0e4736"
}
```

Headers: `X-Blaxel-Source: platform`, `X-Blaxel-Error-Code` and `X-Blaxel-Dispatch-State`. An error that is not safe to resend also sends `X-Should-Retry: false`; a code that names a wait sends `X-Should-Retry: true` and `Retry-After` in seconds. `/v1` errors keep their generic `code` and `message`, carry these fields in `details` with the code in `details.error_code`, and send only the retry headers.

### Sandbox API

The sandbox API sends the same fields at the top level of its error body. `error` still holds the message, `code` is the string code (also in `error_code`) and `request_id` is the request's `X-Request-Id`. The `error` event of a streamed exec or log stream (NDJSON) carries the same fields, with the message in `data`.
